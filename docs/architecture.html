hive-telemetry

A personal Go project: IoT readings from hive scales and weather stations, ingested over MQTT, stored in PostgreSQL, aggregated by background jobs, exported for analytics, and shipped through a CI/CD pipeline.

Go services (one module) Data stores Outside the Go services Operations and delivery

How a reading flows

  1. The simulator publishes a JSON reading to hives/{id}/weight or stations/{id}/weather. Field names follow the Smart Data Models WeatherObserved shape.
  2. The ingestor subscribes, validates the payload, and upserts it keyed by device and observed_at. MQTT QoS 1 can deliver a message twice, so the write has to be idempotent.
  3. Every hour a River job computes averages into hourly_avg. River takes jobs with SELECT … FOR UPDATE SKIP LOCKED, so two workers never run the same job.
  4. Every night a River job writes the previous day to a Parquet file. DuckDB queries those files for analytics without touching the OLTP database.
  5. The API serves readings and summaries over endpoints generated from openapi.yaml. The web page calls the API.
  6. Each step is traced with OpenTelemetry, so one reading can be followed from MQTT to the database in Jaeger.

Build order, about 7 sessions

  1. Go basics. Interfaces, errors, context, goroutines, errgroup. Small exercises.
  2. API + Postgres. openapi.yaml, ogen, pgx, migrations, graceful shutdown.
  3. MQTT ingestion. Mosquitto in compose, simulator, idempotent upsert.
  4. Jobs + analytics. River hourly averages, nightly Parquet export, DuckDB.
  5. Observability. OpenTelemetry for HTTP, pgx and River, Jaeger, slog with trace IDs.
  6. Quality + CI/CD. golangci-lint, table-driven and integration tests, Actions, GHCR.
  7. Kubernetes + web page. kind, manifests, the HTML/JS page.

Out of scope for now

  • Server-rendered templates: the page is plain HTML and JS.
  • OIDC, passkeys, policy engines: no auth beyond an API key.
  • NGSI-LD context broker: only the Smart Data Models field names.
  • TimescaleDB: a possible experiment once plain PostgreSQL works.
